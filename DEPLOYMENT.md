# Deploying Kenya Watch

Kenya Watch runs as one Docker container that serves the API, the citizen and
staff app, and the Agency Case Portal from the same HTTPS address. MongoDB is
external. The steps below use Render for hosting and MongoDB Atlas for the
database; any host that runs a Dockerfile works the same way.

## 1. Database (MongoDB Atlas)

1. Create a cluster (the free M0 tier is enough for a demonstration).
2. Create a database user with a long random password.
3. Under Network Access, allow the host's outbound addresses (or 0.0.0.0/0 for a
   demonstration only).
4. Copy the connection string, adding the database name:
   `mongodb+srv://USER:PASSWORD@CLUSTER/kenya_watch?retryWrites=true&w=majority`

## 2. Admin account (run once, on your own computer)

The Admin password is never stored in the repository or the hosting dashboard
in plain text.

1. In `backend/.env` set `MONGO_URI` to the Atlas string above and
   `ADMIN_EMAIL` to the Admin's address (not the sending mailbox).
2. `cd backend && node scripts/set-admin-password.js` and enter the password.
   The script writes `ADMIN_PASSWORD_HASH` into `backend/.env`; copy that value.
3. `node scripts/bootstrap-admin.js "Admin Name" "admin@example.org"`.

## 3. Email

Sign-in codes and password resets are sent by email, and the server refuses to
start in production without SMTP. With Gmail, turn on two-step verification and
create an app password; use `smtp.gmail.com`, port 587, the Gmail address as
`SMTP_USER` and the app password as `SMTP_PASS`.

## 4. Web service (Render)

1. Push the repository to GitHub.
2. In Render choose **New > Blueprint**, select the repository, and Render reads
   `render.yaml`.
3. Enter the values Render asks for:

| Variable | Value |
|---|---|
| `MONGO_URI` | the Atlas connection string |
| `FRONTEND_ORIGIN` | the service URL, e.g. `https://kenya-watch.onrender.com` |
| `AGENCY_PORTAL_ORIGIN` | the same URL |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH` | from step 2 |
| `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` | from step 3 |

`JWT_SECRET` is generated by Render. `TRUST_PROXY=1` makes the rate limits see
each visitor's address rather than Render's proxy. `MFA_REQUIRED` stays `true`.

4. Deploy. The build compiles the React app and trains the experimental model
   from the synthetic corpus (about 20 seconds). When `/api/health` answers, the
   service is live at the URL above, with the agency portal at `/agency-portal/`.

The server checks its own settings at start-up and refuses to run in production
with a weak `JWT_SECRET`, no SMTP, no Admin password hash, a non-HTTPS
`FRONTEND_ORIGIN` or MFA turned off. If a deploy fails, the log names the
setting.

## Optional settings

- Phone alerts: `node scripts/generate-vapid-keys.js`, then set `VAPID_PUBLIC_KEY`,
  `VAPID_PRIVATE_KEY` and `VAPID_SUBJECT`.
- `CAPTCHA_SECRET` (otherwise the JWT secret is used), `RETENTION_DAYS` (default 90),
  `REFERRAL_ACK_DAYS`, `REFERRAL_STALE_DAYS`, `REFERRAL_REMIND_DAYS`.

## Before any real use

This deployment is for demonstration. Real reports should not be collected until
the recommendations in Chapter 6 of the project documentation are met: an
agreement with a receiving institution, an independent security and data
protection assessment, and an authenticator-app second factor for staff. As a
data controller the operator must also register with the Office of the Data
Protection Commissioner under the Data Protection Act, 2019. The category model is
trained on synthetic data and is labelled experimental in the reviewer screen.

## Running the container locally

```
docker build -t kenya-watch .
docker run -p 5000:5000 --env-file backend/.env -e NODE_ENV=production kenya-watch
```

Locally, `FRONTEND_ORIGIN` must still be an `https://` URL for the production
checks to pass, so use a tunnel or keep `NODE_ENV=development` for local tests.
